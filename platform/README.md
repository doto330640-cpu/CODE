# ECM 코스관리 플랫폼 (앱)

골프장 센서 데이터(ATMOS 41 기상 + TEROS 12 토양)를 **경영자 보기**와 **코스팀장 보기** 두 가지로 보여 주는 설치형 웹앱(PWA)입니다.

| 보기 | 목적 | 화면 |
|---|---|---|
| 경영자 | 전 코스를 한눈에 비교하고 조치 우선순위를 정함 | 한 줄 브리핑, 핵심 지표 4개, 코스 카드 5장, 코스별 수분 비교, 7일 수분수지, 조치 우선순위 |
| 코스팀장 | 오늘 할 일을 정하고 현장에서 체크 | 오늘의 판단, 포트별 수분, 추이 차트 4종, 오늘 작업 체크리스트(자동 제안 + 직접 추가) |

## 실행
```bash
python3 -m http.server 8123      # 저장소 루트에서
# 브라우저: http://localhost:8123/platform/index.html
```
- 주소 `#exec` = 경영자, `#team/코스이름` = 코스팀장. 마지막에 본 보기를 기억합니다.
- 휴대폰에서 열고 "홈 화면에 추가"하면 앱처럼 설치됩니다 (HTTPS 주소 필요). 한 번 열면 오프라인에서도 열립니다.

## 데이터 구성
| 파일 | 내용 | 만드는 법 |
|---|---|---|
| `data/courses.json` | 센서(기상·토양) 일별, 5개 코스 | `tools/build_platform_data.py <센서 엑셀 폴더>` |
| `data/drone.json` | 드론 분석: 촬영일별 TSI·식생지수·병해 위험, 홀·구역별 변화 | `tools/build_drone_data.py <ECM 드론 분석 엑셀>` |
| `data/sensors.json` | 센서 포트 설치 위치 (도면은 `images/source/`) | 손으로 관리 |

드론 파일의 "세종CC"는 센서 파일의 "세종필드"와 같은 코스로 보고 합쳤습니다(확인 필요).

## 드론 분석 읽는 법
- TSI(0~100): 80↑ 최상 · 65~79 양호 · 50~64 주의 · 35~49 경고. 엽록소 밴드가 없는 촬영의 TSI는 참고값입니다(5개 코스 대부분 해당).
- 식생지수 변화는 첫 촬영 대비이며, 0.03 이상 하락한 구역을 "나빠지는 구역"으로 표시합니다.
- 식생지수가 하루 이틀 사이 ±0.08 이상 튀었다가 돌아온 촬영은 촬영 조건 영향일 수 있어 화면에 주석으로 표시합니다.

## 데이터 갱신
```bash
python3 tools/build_platform_data.py <센서 엑셀 폴더>   # → platform/data/courses.json
```
코스별 엑셀 형식이 달라 시트 이름으로 코스를 구분합니다. 증발산량은 측정 건수 90건 미만인 부분일은 비웁니다.

## 판정 기준 (내부 가정값 — 현장 확정 필요)
- 코스마다 토양이 달라 수분(%) 절대 기준을 쓰지 않고, 그 코스의 관측 기간 안에서의 위치와 최근 7일 수분수지(강수 − 증발산)를 봅니다.
- 관수 점검: 하위 25% 이하 + 수분수지 −5mm 미만 / 주의: 하위 40% 이하 또는 −10mm 미만 / 센서 중단: 2일 이상 미수신.
- 기준 값은 `app.js`의 `metrics()`에서 바꿉니다.

## 아직 없는 것 (다음 단계)
- 로그인·권한(경영자만 볼 화면 분리), 여러 사용자 간 작업 공유 → 서버 필요
- 홀·구역 지도 (센서 포트와 홀의 대응 정보 필요)
- 내장객·객단가·비용 등 경영 지표 (자료 필요)
- 센서 자료 자동 수집 (현재는 엑셀 → 변환)
